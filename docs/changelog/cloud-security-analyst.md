# cloud-security-analyst changelog

| Version | Date | Change |
|---|---|---|
| 2.2 | 2026-11-20 | Removed references to deleted agents: detection work now goes to the **detection / SOC engineering team** and pipeline / IaC fixes to the **DevSecOps / platform team** (handoffs and section notes). No analysis change. |

| 2.0 | 2026-11-17 | Full rebuild in the portable standard format (replaces the truncated v1, which ended mid-section and contained a copied tool artefact). **Two modes:** `posture` (attack paths) and `triage` (cloud alerts), chosen in Step 0. Shared core: core rules, tool roles (file read, web search, page fetch, read-only cloud platform tool), assumptions register, evidence rules. **Posture:** inventory with labels, identities and trust relationships, data classification (unclassified = sensitive), exposure, organisation guardrails, logging/detection coverage, cloud AI services; findings from several scanner exports mapped and de-duplicated with tool coverage; cloud graph; attack paths rated by a factor table (Exposure, exploitable Weakness, Privileged identity, sensitive Data, Lateral movement, runtime evidence) with exposure state; IAM privilege escalation by category with prerequisites and role chains up to 4 hops; control/guardrail validation with the 9 ordered tests (+ "acted on" for detective controls), blocked paths; logging gaps; shift-left notes; recommendations with driver, preventive + detective, IaC location and "how to verify"; Mermaid attack-path diagrams compatible with the exporter; CSV and JSON. **Triage:** correlate first (identity, IP, resource, window), classify (drift, credential compromise, workload compromise, data exposure, expected change), weight write/defence-evasion actions, always-escalate categories, 7-row disposition table (suppress by evidence, escalate by category), exposure state, containment by control plane. Guardrails: evidence, agent self-protection (read scope, instruction hierarchy, hidden instructions in tags/comments/logs, input validation, no URLs from material, masking, no exploit content, read-only platform tools), safety and scope. Fixed **usage card** printed verbatim on `?` / `help` / `usage` (inputs per mode, context template, example prompts, export commands, what you get, what not to give). |
