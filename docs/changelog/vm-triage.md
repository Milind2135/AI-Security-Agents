# vm-triage changelog

| Version | Date | Change |
|---|---|---|
| 5.5 | 2026-11-20 | Routing: "were we breached / are others affected" now goes to `soc-analyst` (`mode: hunt`) instead of the deleted `threat-hunter` agent (usage card). No other change. |
| 5.4 | 2026-11-03 | Handoff carries remediation and decision inputs, so `vulnerability-hunt` never fills them from memory (found in vulnerability-hunt test scenario 1: it recommended a fixed version and the `formatMsgNoLookups` workaround — which this agent marks *later declared insufficient* — as if from the handoff). JSON gains `exploit_public` (from Section 9), `ssvc` (CISA ADP exploitation / automatable / technical impact, quoted or `null`), `fixed_versions` (one entry per Section 17 row with `Verbatim`/`Unverified` status) and `workarounds` (one entry per Section 18 row with `current`/`later declared insufficient`). New pre-send check that these match Sections 9, 17 and 18. Markers bumped to v5.4. No change to sections, procedure, budget or guardrails. |
| 5.3 | 2026-11-02 | Added a **help/usage mode** for new users. New Step 0.0 "Help shortcut": when the input is empty or only a help token (`?`, `help`, `--help`, `usage`, "how do I use this", etc.), the agent prints a verbatim usage card — purpose, required CVE input, optional `depth`, copy-paste examples, scope boundaries (points to `vulnerability-hunt` / `threat-hunter`), and how to start it — then stops, using no tool budget; it never triggers when the input contains a valid CVE ID. New `vm-triage vX.Y \| help` marker line. The "missing CVE" ask now suggests typing `?`; `argument-hint` and the Runtime-notes start instructions mention `?`. No change to the 26 sections, procedure, budget or guardrails. |
| 5.2 | 2026-11-02 | From the second Claude Code test (CVE-2024-3400, pass). Core facts: NVD JSON (S2), CVE Services (S3) and EPSS (S4) are now the **primary** sources; the NVD detail page (S1) is a fallback fetched only when S2 fails or lacks KEV/CVSS/references (it returned the NVD home page in both test runs); S2 request now includes references; new fallback when both S2 and S1 fail; S1 may be listed as `NOT_FETCHED (S2 sufficient)`. JSON handoff: detection `id` must be the report's D1/D2…; IOC `sources` lists every cited S#. Step 1 budget is 3 URLs (+ S1 / S3-alt only if needed). `CLAUDE.md` relay rule now requires the full report from first line to last line. Baselines saved in `tests/vm-triage/baselines/`. |
| 5.1 | 2026-11-02 | From the first Claude Code test (Opus 4.8, CVE-2021-44228; report passed most checks). (1) Conflict check 1 now compares the CNA structured version data with **the CVE description text itself** (the `descriptions` field, now requested verbatim from S2/S3), not vendor prose; vendor-prose comparison is recorded separately. (2) Fixed and recommended versions in Section 17 must be quoted verbatim from a source naming that CVE, with a new `Version status` column (`Verbatim` / `Unverified`); unverified numbers are never stated as fact. Matching pre-send checklist items and guardrail added. Claude Code entry file marker updated to v5.1. |
| 5.0 | 2026-11-02 | Made portable across **Claude Code** (testing) and **GitHub Copilot in VS Code** (work environments); Cline is legacy. One instruction file (`.github/agents/vm-triage.agent.md`) plus a Claude Code entry point (`.claude/agents/vm-triage.md`, tools limited to Read, WebSearch, WebFetch). Added: runtime-neutral tool roles (page fetch, web search) with a mapping table; search optional, with a no-search discovery path (core-record references, GitHub Advisory, OSV); verbatim-fetch rule for fetch tools that return processed answers (summaries are FETCHED_PARTIAL and never presented as exact values); suggested verbatim requests for S1–S4; self-contained core rules (no reliance on AGENTS.md being loaded); final message must be the complete report (also when run as a subagent); budget counted in URLs so it works with single- and multi-URL fetch tools; Cline-only steps moved to runtime notes; `runtime_tools` added to the JSON handoff. Section numbering and contracts unchanged from 4.3. |
| 4.3 | 2026-10-27 | From the first full test run (CVE-2021-44228, poolside/laguna-s-2.1:free): size limits (search max 5 results, no raw content; extract max 3 URLs; notes instead of pages); budget is a hard stop; search snippets are SNIPPET_ONLY and never evidence; fix section gives earliest fixed version, vendor-recommended version and follow-on CVEs; four mandatory conflict checks in Section 24; pre-send checklist (status words, status line in every section, citation/publisher match, defanged IOCs, JSON completeness); fewer, behaviour-based ATT&CK mappings with exact Mapping Origin values; mitigation status (current / later declared insufficient); labelled and dated secondary EPSS allowed when the EPSS API is unreadable (`epss_secondary` in JSON); never create or edit any file including the agent file. Retrieval budget changed from 3×5 to 4×3 URLs (standard). Pre-test hardening (same day): JSON core-fact sources (S2/S3/S4) now have explicit fallbacks when a runtime cannot read JSON — S2→S1, S3→`cve.org` HTML record (S3-alt), S4→secondary EPSS; Section 24 conflict checks name their source and, if CNA data is unreadable, degrade to the vendor advisory rather than being dropped; Step 0 states a JSON FAILED is expected, not a stop. |
| 4.2 | 2026-10-24 | Guardrails section reorganised into Evidence and Safety & scope groups; the v4.1 "never" rules (core-fact precedence, not-retrieved-is-not-zero, scoped negatives, ATT&CK inference cap, ignore embedded instructions) now also appear as one-line guardrails pointing to the step that applies them. No procedural change. |
| 4.1 | 2026-10-24 | Core facts (S1–S4) take precedence over all other text; failed lookups reported as NOT_AVAILABLE, never zero/default; "not found" statements name the sources checked; text addressed to AI systems in fetched pages is flagged in Section 25; ATT&CK table adds confidence, inferred mappings capped at Medium; close-out adds data timestamp, re-run triggers, handoff split into version / configuration / exposure / compromise-evidence conditions, and a JSON handoff block; guardrail against equating version match with exposure. |
| 4.0 | 2026-10-24 | Restructured into the standard agent format (Inputs table, Steps 0–6, Budget, Guardrails, Runtime notes). Shared rules moved to `AGENTS.md`. Added `depth` input (standard/thorough budgets), finding IDs VT-01… with statuses in Section 26, handoff block for vulnerability-hunt, open questions and improvement proposals. Guardrail against reproducing exploit code. |
| 3.2 | 2026-10-24 | Single self-contained `.agent.md` for Cline and Copilot; chat output; no scripts. |
| 3.0 | 2026-10-24 | Standalone (no `enrich.py`); core facts fetched via one batched Tavily call. |
| 2.0 | 2026-10-24 | Chat mode; request budget and URL batching for OpenRouter free tier. |
| 1.x | 2026-10-19/20 | File-based workflow with `enrich.py` and `validate_report.py`; preflight marker added. |
