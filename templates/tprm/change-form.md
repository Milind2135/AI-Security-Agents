# Third-party change form (scheduled review or trigger event)

Use this for an **existing** vendor: at its scheduled review, or when something happened. Answer **what changed since the last assessment**; write `No change` where nothing changed and `Don't know` if you are unsure (the agent then treats the factor as High until confirmed).

Save it as `docs/vendors/<vendor>/change-<YYYY-MM-DD>.md`. Give the agent the latest saved record (`previous:`) with it.

| Field | Answer |
|---|---|
| Vendor and engagement | |
| Business owner (name, role) | |
| Reason: scheduled review · contract renewal · incident or breach · ownership change · service change · regulator request · other | |
| Date of the event (if any) | |

## What changed?
| Area | Question | Answer |
|---|---|---|
| Service | New services, more users, new business functions, more critical use? | |
| Data (A1–A9) | More or new kinds of data, more records, new countries for data, data kept longer? | |
| Access (B1–B8) | New connections, integrations, higher access level, more vendor users, AI agents acting on our systems? | |
| Business impact (C1–C7) | Do we now depend on it more or less? Faster harm if it stops? Alternatives added or removed? | |
| Regulatory (D1–D5) | New regulated activity, new countries, sanctions or licence changes? | |
| Technology (E1–E4) | New cloud providers or regions, new AI features, new subcontractors, financial trouble? | |
| Incidents | Security incidents, outages or breaches at the vendor since the last review? | |
| Performance | Repeated SLA failures, complaints, audit issues? | |
| Ownership | Merger, acquisition, new owners? | |
| Contract | Renewal date, new terms, termination planned? | |

## Open items from the last assessment (TPRM to complete)
List any actions, conditions or exceptions you know have been completed, with the evidence file names.
